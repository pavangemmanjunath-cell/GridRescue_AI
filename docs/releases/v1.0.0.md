# GridRescue AI v1.0.0

Release date: 2026-10-31

## Overview

First public release of GridRescue AI, an open-source planner for clean backup power at hospitals and other critical facilities on weak grids. From a map pin it reads the site from open data, sizes and simulates candidate systems hour by hour through outage cases, costs them, plans the move of a facility that must relocate, and produces an ESG estimate. It is the proof of concept for the Global Energy Hackathon 2026, Brief 12 "Relocatable solar for a hospital on the move", with the National Orthopaedic Hospital, Enugu as the worked example. Results are pre-feasibility estimates (about ±30 %).

## Highlights

- One flow from a map pin to a tested, costed, relocatable backup-power plan, in seconds, without API keys.
- Every design is checked by a 24-hour dispatch simulation, four stress tests and an outage survival curve.
- An ESG report for the selected site and lens with Scope 1 and Scope 2 estimates.
- A Random Forest gives a first pick (80.4 % agreement with the engine on held-out synthetic sites); the simulation verifies every pick.
- Reproducible: a deterministic engine, a seeded classifier that retrains byte for byte, a quick-start example and a regression test of the worked example.

Worked example, from live open data (reproduce with `python examples/quickstart.py`):

| Theatres and ICU | Diesel avoided | CO₂ avoided | Upfront and fee | 10-year cost | After the move |
|---|---|---|---|---|---|
| 303 kW on a 0 ms UPS; 4 of 4 stress tests | 866,678 L a year (83 %) | 2,246 t a year, net | ₦0 upfront; fee ₦69.1 M a month vs ₦299 M of modelled diesel | ₦15.9 bn vs ₦37.6 bn on diesel | 88 % of the investment reused |

## New Features

- **Planning engine**: site scoring, a critical/essential/non-essential load model, sizing and costing of nine architectures (UPS, grid-charged storage, solar + storage, wind + storage, solar + flow, solar + hydrogen, pumped hydro, generator hybrid and the site's own stack), nine weighted ranking criteria, an investment case and an agent trace.
- **Outage simulation**: 24-hour dispatch with tiered load shedding; stress tests for a 12-hour evening outage, a 24-hour national grid collapse, the worst solar month and an 18-hour outage; outage survival at every start hour for 4–24 hours.
- **Relocation case**: phases, critical-load list, movable design, move plan, ownership model, 5- and 10-year costs of diesel, grid and solar, funders, and the Three A's (access, affordability, availability).
- **ESG report** (`POST /api/report/esg`): Scope 1 and Scope 2 emissions, E · S · G report lines, and carbon value at a user-entered price, marked as potential until verified and issued.
- **ML classifier** (`POST /api/ml/predict`, `GET /api/ml/model`): Random Forest of 30 CART trees plus a CART tree for readable rules, 21 inputs, ten infrastructure types.
- **Ask GridRescue** (`POST /api/ask`): retrieval over an internal SQLite FTS5 index with extractive, cited answers; assessment history. No language model is used.
- **Web application**: Explorer with sun, wind, water, grid and new-site lenses; relocation plan; Facility calculator; Advisor; Compare; Costs; Simulate (3D site tagged with the selected location and lens); Build 3D; Learn; Report; hands-free page.
- **Offline mode** (`GR_OFFLINE=1`) from bundled snapshots.
- **One-click start**: `START.bat` checks Python and Node.js, installs, starts both servers, waits for them and opens the app; `start.sh` does the same on Linux and macOS. `GR_UI_PORT` selects another app port if 5173 is taken.

## Research Improvements

- Reproducible classifier evaluation with a single-tree and majority baseline: 80.4 % held-out accuracy (top-2 94.5 %) vs 76.9 % and 46.5 %; results in `benchmarks/results/ml_classifier_v1.0.0.json`.
- Model card, data card, methodology, technical positioning and limitations documented in the repository.

## Methodology Changes

- **CO₂ counted once.** Solar used during an outage is counted only as diesel not burnt (Scope 1). Scope 2 is the change in grid electricity bought while the grid is on, which can be negative when batteries charge from the grid. For the worked example this gives 2,323 t − 77 t = 2,246 t a year. An earlier pre-release figure of 3,222 t counted outage-time solar twice; the documents and videos in `FINAL_DOC/` use the corrected figure.

## Reproducibility

```bash
python examples/quickstart.py                    # worked example, live open data
python examples/quickstart.py --offline          # same design; 845,654 L and 2,344 t with modelled weather
cd backend && pytest                             # 63 tests, offline
python -m app.ml.train_backup_classifier --out ../benchmarks/results/backup_classifier_repro.json
```

Verified for this release:

- CI on Ubuntu passes for Python 3.11, 3.12 and 3.13 (63 tests and the offline quick-start) and Node.js 22 (lint, type-check, 23 unit tests, production build), validates `CITATION.cff`, and starts the app with `start.sh`.
- On Windows 11 (Python 3.13, Node.js 24), `START.bat` was run from a fresh clone in a folder whose path contains a space: the first run installed everything and started both servers in about 4 minutes, and all Playwright GUI specs pass against the app it started.
- Retraining the classifier with seed 2026 reproduces the shipped model file byte for byte.

## Known Limitations

- One 24-hour design day per assessment; no full-year simulation yet.
- Loads come from benchmarks until the facility's metered profile is supplied; in the worked example the land area, generator size and diesel bill are assumed and flagged.
- The classifier is validated only against the engine, on synthetic sites, and does not pick rare families (wind-only, flow, hydrogen).
- No authentication or rate limiting; not hardened for production.
- react-leaflet is published under the Hippocratic License 2.1.

See `docs/limitations.md`.
