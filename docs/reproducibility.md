# Reproducibility Guide

## Supported Environment

| | Tested |
|---|---|
| OS | Windows 11 (development); Ubuntu (GitHub Actions CI) |
| Python | 3.13 locally; 3.11, 3.12 and 3.13 in CI |
| Node.js | 24 locally; 22 in CI (Node 22.12 or newer is required by vitest and jsdom; the dev server alone needs 20.19 or newer) |
| Hardware | Any laptop; no GPU needed for the engine. The 3D pages use WebGL and are smoother with a GPU |
| Network | Optional. `GR_OFFLINE=1` runs everything from bundled snapshots |

## Installation

```bash
git clone https://github.com/pavangemmanjunath-cell/GridRescue_AI.git
cd GridRescue_AI/backend
python -m venv .venv
# Linux / macOS: source .venv/bin/activate      Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cd ../frontend
npm ci
```

Windows users can run `START.bat` instead; it installs both parts and starts the app.

## Dataset Preparation

None for the engine: open data is fetched on demand and cached, and offline snapshots are bundled. The classifier's training sites are generated by the training script. See [DATA_CARD.md](../DATA_CARD.md).

## Configuration

Environment variables (optional; put them in `backend/.env`, which is git-ignored):

| Variable | Effect |
|---|---|
| `GR_OFFLINE=1` | Use bundled snapshots and modelled values only |
| `GR_CACHE_DIR` | Cache and SQLite location (default `.cache` under `backend/`) |
| `GR_USER_AGENT` | User agent sent to open-data services (add a contact, as Nominatim asks) |
| `GR_HEALTHSITES_API_KEY` | Enables live healthsites.io facility data |
| `GR_LLM_PROVIDER` | Reserved for a future language-model backend for Ask |

## Random Seeds

The engine is deterministic. The classifier uses seed 2026 for site sampling, bagging and feature subsets (`--seed` to change it).

## Reproduce Experiments

Classifier training and held-out evaluation, written to a separate file so the shipped model is untouched:

```bash
cd backend
python -m app.ml.train_backup_classifier --out ../benchmarks/results/backup_classifier_repro.json
```

It prints the model metadata, including `accuracy_test`, `top2_accuracy_test`, `cart_accuracy_test` and `majority_baseline_test`. Expected values are in [benchmarks/README.md](../benchmarks/README.md).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `npm ci` fails with an engine error | Install Node.js 22.12 or newer |
| The app shows "API offline" | Start the backend on port 8000, or run `START.bat` |
| Open-data calls time out | Set `GR_OFFLINE=1` |
| 3D pages are slow | Use a browser with hardware acceleration enabled |
| Port 8000 or 5173 is in use | Close the other instance; `START.bat` detects a running copy and opens it |

## Known Sources of Non-Determinism

- **Live open data**: values from NASA POWER, Open-Meteo or OpenStreetMap can change between runs; offline mode removes this. Offline and live runs differ by design: offline hourly weather is modelled (for the worked example, 845,654 L and 2,344 t instead of 866,678 L and 2,246 t).
- **Live prices**: published tariffs and diesel prices are updated in the data files over time.
- **Cache**: a cached response is reused until it expires, so two runs a day apart can differ when online.
- **Floating point**: last-digit differences between platforms are possible; the tests compare rounded values.

## Reproducibility Limitations

- The GUI tests need a browser and both servers, so CI runs only the backend tests, the type-check, the unit tests and the build.
- The videos and documents in `FINAL_DOC/` were produced with local tools (text-to-speech voices, Word, PowerPoint) whose pipeline is not part of this repository.
