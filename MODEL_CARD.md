# Model Card — backup-architecture classifier

## Model Details

| | |
|---|---|
| Name | GridRescue AI backup-architecture classifier |
| Version | trained with engine 1.0.0, seed 2026 (`backend/app/data/backup_classifier_model.json`) |
| Type | Random Forest of 30 CART decision trees (Gini impurity, bootstrap samples, √21 ≈ 5 random features per split), plus one CART tree trained on the same data to give readable rules |
| Implementation | Pure Python, no ML library: `backend/app/ml/backup_classifier.py`; training: `backend/app/ml/train_backup_classifier.py` |
| Inputs | 21 features: the facility (kind as one-hot flags, average and protected load, critical share, required backup hours, roof and land area, existing generator), the site (grid supply hours and class, annual and worst-month solar, 50 m wind, terrain head, flowing water) and the diesel price |
| Output | Probability for each system family (solar + storage, solar + storage + generator, generator + storage, grid-charged storage, solar + wind + storage, wind + storage, solar + flow, solar + hydrogen, …), the top three, and the decision path of the CART tree |
| Authors | Pavan Manjunath, Thomas Prüfer |
| Licence | Apache-2.0 (model file and code) |

## Intended Use

A fast first answer to "which family of backup system suits this facility at this site?", shown on the Advisor, Facility and Simulate pages and in the agent trace. **The hourly simulation decides.** The engine sizes and simulates every candidate after the pick, and the page says so when the simulation prefers another design.

## Out-of-Scope Use

- Final design or investment decisions without the simulation, an engineering study and local quotes.
- Sites or facilities outside the training ranges below, such as very large loads, polar latitudes or island grids.
- Any claim about real-world accuracy. The model imitates the engine; it has not been validated against installed systems.

## Training Data

10,000 synthetic sites generated by the training script and **labelled by the full GridRescue engine** (sizing, 24-hour dispatch through a 12-hour outage from 18:00, nine-criterion scoring with "balanced" priority). Ranges follow conditions observed across Nigeria and sub-Saharan Africa: solar 3.6–6.6 peak-sun hours, 50 m wind 2.5–7.5 m/s, grid classes A–E weighted toward Nigerian distribution-company conditions, and ten kinds of infrastructure weighted toward healthcare. The data is generated on demand and not stored; see [DATA_CARD.md](DATA_CARD.md).

The first 8,000 sites train the models; the last 2,000 are held out for testing.

## Evaluation Data

The 2,000 held-out synthetic sites from the same generator and seed. They are not real sites.

## Metrics

Accuracy, top-2 accuracy, per-family recall, compared with one CART tree and with always guessing the most common family.

## Performance

Measured on the 2,000 held-out sites:

| Model | Accuracy |
|---|---|
| Random Forest (30 trees) | **80.4 %** |
| Random Forest, top-2 | 94.5 % |
| Single CART tree | 76.9 % |
| Most-common-family baseline | 46.5 % |
| Random Forest on its training sites | 86.5 % |

Recall by family on the held-out sites (families with at least 10 test sites):

| Family | Recall |
|---|---|
| Solar + storage | 89.5 % |
| Solar + storage + generator | 80.9 % |
| Generator + storage | 72.4 % |
| Grid-charged storage | 57.9 % |
| Solar + wind + storage | 55.2 % |
| Wind + storage | 0 % |
| Solar + flow | 0 % |

Label distribution over all 10,000 sites: solar + storage 4,541; solar + storage + generator 2,785; generator + storage 1,604; grid-charged storage 594; solar + wind + storage 338; solar + flow 70; wind + storage 54; hydrogen 14.

These figures measure agreement with the engine, not correctness in the field.

## Limitations

- Rare families (wind-only, flow, hydrogen) are under-represented and are effectively never predicted. The simulation still evaluates them.
- The model inherits every assumption of the engine that labelled it.
- The probabilities are vote shares and are not calibrated.
- One design day and one outage window are used for labelling.

## Bias and Fairness Considerations

The sampling ranges are weighted toward Nigerian and sub-Saharan conditions. Sites elsewhere may be outside the training distribution, where the pick is less reliable. Facility kinds are weighted toward hospitals, so other infrastructure has fewer training examples. No personal data is involved.

## Ethical Considerations

The tool informs decisions about power for hospitals. A wrong pick could delay a good decision but cannot override the simulation, which every pick passes through. Results are labelled as pre-feasibility estimates.

## Security Considerations

The model file is static JSON loaded at start. It holds no personal data. Replacing it changes the first pick but not the simulation's verdict.

## Reproducibility

```bash
cd backend
python -m app.ml.train_backup_classifier --out /tmp/backup_classifier_model.json   # about ten minutes on a laptop
```

The run is deterministic for a given seed. See [docs/reproducibility.md](docs/reproducibility.md) and [benchmarks/README.md](benchmarks/README.md).
